# Политика безопасности

AI Operations Agent — локальное однопользовательское приложение. Оно работает на
компьютере пользователя, по умолчанию слушает только `127.0.0.1` и не отправляет код,
операционные данные или историю расследований внешнему провайдеру. Сеть используется
только для явных запросов к подключённым системам (GitHub, Prometheus) и к локальной
Ollama.

## Поддерживаемые версии

Проект находится до первого стабильного релиза. Патчи безопасности выпускаются для
последней опубликованной версии; более ранние не поддерживаются. Актуальный список
версий и известных ограничений — в описании релиза на GitHub.

## Как сообщить об уязвимости

Не открывайте публичный issue для уязвимости. Используйте приватный канал GitHub
**Security → Report a vulnerability** в этом репозитории.

В обращении укажите:

- затронутую версию (тег образа или `pyproject.toml`);
- шаги воспроизведения и влияние;
- при необходимости — диагностический отчёт без секретов, полученный командой
  `./manage.sh report agent-report.json` (или `manage.ps1 -Command report`).

**Не прикладывайте токены, пароли, приватные ключи и содержимое volume.** Отчёт уже
маскирует такие значения, но проверяйте файл перед отправкой.

## Что входит в область рассмотрения

- локальный веб-интерфейс и HTTP API на `localhost`;
- GitHub Device Flow, хранение и обновление токенов;
- слой интеграции MCP и встроенные MCP-серверы;
- контейнер, Compose-конфигурация и релизные артефакты;
- маскирование секретов и безопасность диагностического отчёта.

## Что не входит

- уязвимости в Ollama, Docker, моделях и сторонних сервисах (сообщайте их авторам);
- риски, требующие уже скомпрометированного хоста или прав администратора;
- конфигурации, где порт намеренно открыт наружу или отключено подтверждение записи.

## Меры по умолчанию

- веб-порт привязан к loopback; запись наружу требует подтверждения человека;
- токены GitHub шифруются, ключ хранится отдельно от базы;
- секреты исключаются из логов и диагностического отчёта;
- образ запускается от непривилегированного пользователя и подписывается в релизе;
- ответы MCP считаются недоверенным вводом и повторно валидируются.
