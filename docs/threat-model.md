# Модель угроз локального приложения

Документ описывает, от чего приложение защищается и что осознанно остаётся вне защиты.
Он относится к локальному однопользовательскому режиму (веха 8 плана), а не к
гипотетическому серверному развёртыванию.

## Активы

- история расследований, трассировки и ожидающие подтверждения;
- токены GitHub (access и refresh);
- выбранный репозиторий и настройки подключений;
- ключ шифрования токенов и локальный volume;
- диагностические отчёты, которые пользователь передаёт в поддержку.

## Границы доверия

1. **Браузер пользователя ↔ контейнер.** Порт по умолчанию слушает только `127.0.0.1`.
2. **Контейнер ↔ Ollama на хосте.** Обычный HTTP к локальному адресу.
3. **Контейнер ↔ GitHub.** Device Flow и REST API по HTTPS, только чтение до подтверждения.
4. **Контейнер ↔ MCP-серверы.** Встроенные серверы в процессе; ответы — недоверенный ввод.
5. **Файловая система.** Volume с базой, ключом и каталогом runbook.

## Угрозы и меры

### Доступ снаружи

- **Угроза:** интерфейс с полным доступом к данным и записи оказывается доступен из сети.
- **Мера:** привязка порта к loopback в пользовательском Compose; запуск от
  непривилегированного пользователя. Открытие порта наружу — сознательный отказ от защиты,
  вне области рассмотрения.

### Запись без подтверждения

- **Угроза:** issue создаётся автоматически по ошибочному выводу агента.
- **Мера:** write-инструменты выполняются только после показа точного текста и
  подтверждения человеком; метрика `agent_unapproved_writes_total` должна быть нулём;
  перед записью повторно ищется открытый дубликат.

### Утечка токенов GitHub

- **Угроза:** токен попадает в базу, лог, трассировку или диагностический отчёт.
- **Мера:** токены шифруются, ключ хранится отдельным файлом `0600`; секреты маскируются
  в диагностике ([`app/observability/diagnostics.py`](../app/observability/diagnostics.py));
  отключение GitHub удаляет зашифрованный токен. Потеря только SQLite не переносит авторизацию.

### Недоверенные ответы MCP

- **Угроза:** внешний или скомпрометированный MCP-сервер расширяет полномочия или
  подсовывает данные в вывод.
- **Мера:** allowlist инструментов, разметка read/write, повторная валидация ответов,
  запрет незаметного расширения полномочий после обновления сервера.

### Чтение файлов через runbook

- **Угроза:** path traversal выводит чтение за пределы каталога runbook.
- **Мера:** каталог фиксирован на volume, доступ ограничен разрешённым форматом Markdown.

### Prompt injection и границы вывода

- **Угроза:** модель сошлётся на метрику, которой не видела, или на действие, которого нет.
- **Мера:** модель не пишет список доказательств; ссылки вне собранных данных отбрасываются,
  а гипотеза без подтверждений теряет уверенность.

### Supply chain

- **Угроза:** подмена базового образа, зависимостей или релизного артефакта.
- **Мера:** базовый образ и зависимости зафиксированы; релизный образ собирается из
  проверенного lock-файла с SBOM, provenance и keyless-подписью, а комплект сопровождается
  контрольными суммами ([`docs/release.md`](release.md)).

## Остаточные риски

- полная компрометация хоста или Docker даёт доступ к volume и ключу шифрования;
- открытый по неосторожности порт снимает основную сетевую защиту;
- модель Ollama и внешние сервисы доверяются в пределах их собственной безопасности;
- незакоммиченные локальные изменения пользователя не защищены от потери при `destroy --delete-data`.
