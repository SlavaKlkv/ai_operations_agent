# Устранение неполадок

Локальное приложение почти всегда ломается по одной из перечисленных ниже причин.
Начните с `./manage.sh status` (или `manage.ps1 -Command status`), а для подробностей —
`./manage.sh diagnose`. Если нужен файл для обращения, соберите отчёт без секретов:
`./manage.sh report agent-report.json`.

## Приложение не открывается на http://localhost:8000

1. Проверьте, что Docker запущен: `docker info`.
2. Проверьте контейнер: `./manage.sh status` — он должен быть `healthy`.
3. Посмотрите логи: `./manage.sh diagnose`.
4. Порт занят другим процессом: остановите конфликтующий процесс или используйте
   расширенную конфигурацию Compose с другим host-портом.
5. Контейнер постоянно перезапускается: скорее всего, приложение не может открыть
   каталог данных или применить миграции — см. логи в диагностике.

## Ollama недоступна

- Убедитесь, что Ollama запущена на компьютере: `ollama list`.
- В Docker адрес хоста — `http://host.docker.internal:11434` (задаётся
  `AOA_HOST_OLLAMA_URL`). Для другого адреса задайте `OLLAMA_BASE_URL`.
- Мастер настройки на экране «Диагностика» показывает статус Ollama; ошибка содержит
  конкретное действие.

## Модель не установлена

Откройте мастер настройки и выберите профиль Light или Standard — отсутствующая модель
загрузится с прогрессом. Либо загрузите вручную: `ollama pull qwen3:8b`.

## GitHub не подключается

- Если мастер пишет, что общая GitHub App не настроена, эта сборка не содержит публичных
  `GITHUB_APP_CLIENT_ID` и `GITHUB_APP_SLUG` — подключение недоступно, остаётся demo-режим.
- Иначе нажмите «Подключить GitHub» и завершите Device Flow на github.com. Истёкший код
  требует повторного запуска подключения.
- Отзыв доступа на стороне GitHub потребует подключиться заново.

## Расследование использует demo-данные

Real-run включается только когда подключены GitHub, Prometheus и есть хотя бы один
локальный runbook. Пока их нет, расследование честно работает на синтетических данных и
не выдаёт их за реальные. Настройте `PROMETHEUS_URL` и добавьте Markdown-runbook в каталог
данных (`docs/runbooks.md`).

## Prometheus не настроен

Укажите `PROMETHEUS_URL` вашего read-only Prometheus. Ограничения метрик и допустимые
запросы — в `docs/prometheus.md`.

## Резервная копия и восстановление

```bash
./manage.sh backup backup.db     # согласованная копия SQLite
./manage.sh restore backup.db    # проверка и восстановление
```

`restore` сохраняет вытеснённую базу как `ai_operations_agent.db.before-restore`, поэтому
ошибочное восстановление обратимо. Остановка и обновление volume не удаляют; полное
удаление данных требует `./manage.sh destroy --delete-data`.

## Обновление не применилось

Если схема данных отстала, перед применением миграций автоматически создаётся копия
`<база>.pre-upgrade.bak`. Если после обновления что-то пошло не так, откатитесь на
предыдущий образ и при необходимости восстановите эту копию — см. `docs/release.md`.

## Диагностический отчёт и секреты

Отчёт `./manage.sh report` уже маскирует токены, пароли и учётные данные в строках
подключения. Всё равно проверьте файл перед отправкой и не прикладывайте содержимое volume.
Уязвимости сообщайте приватно — см. [SECURITY.md](../SECURITY.md).
