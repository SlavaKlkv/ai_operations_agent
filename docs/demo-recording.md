# Запись демо-ролика

Ролик интерфейса в README (`docs/assets/demo-dark.mp4`, `docs/assets/demo-light.mp4`)
записывается скриптом `tools/record_demo.py`: он проходит сценарий целиком в
браузере по настоящим событиям мыши и клавиатуры и перекодирует результат в mp4.
Ничего поверх готового видео не монтируется, результаты не подставляются — в кадр
попадает то, что интерфейс действительно показал в ответ на действие.

## Требования к кадру

- Первый кадр — рабочее состояние интерфейса целиком, вместе с курсором. Начало
  записи (страница до применения темы и до первого движения мыши) отбрасывается.
- Только реальные состояния и события. Не дорисовывать подсветку, окна и
  результаты; текст не вставляется мгновенно, а набирается.
- Курсор виден весь ролик. Запись идёт из браузера, поэтому указатель рисуется
  слоем внутри страницы, но ездит строго по настоящим событиям `mousemove` —
  тем же, что вызывают наведение и клик. Формы указателя — покадровые вырезки с
  записи экрана macOS, они лежат в `docs/assets/cursor-shapes` и в репозиторий не
  попадают (исключены через `.git/info/exclude`).
- Кадр 1280x800 без масштабирования; тема применяется до первой отрисовки,
  поэтому белого кадра в начале нет.
- Итог: не более 40 секунд, H.264, `yuv420p`, `+faststart`.

## Длительная обработка

Расследование против локальной Ollama занимает минуты. Полностью оно не
показывается: в кадр попадают начало (панель «Выполняется») и результат, а пауза
между ними вырезается склейкой по отметкам времени сценария. Ничего не ускоряется
и не замедляется — между началом и концом просто нет кадров, поэтому полоса не
дёргается. Это не монтаж поверх реальности: оба оставшихся отрезка идут в
настоящем темпе.

## Прокрутка

Прокрутка ведётся колесом мелкими равномерными шагами (~650 px/с) — крупные шаги
читаются как рывки. Дистанция считается один раз и ограничивается фактическим
максимумом прокрутки, а после каждого прохода позиция перечитывается: плавная
прокрутка догоняет событие колеса не мгновенно, и без повторного измерения
дистанция выходит заниженной. У низа страницы смещение равно нулю, поэтому колесо
больше не крутится — окно останавливается, а не дёргается. Экраны проходятся
сверху вниз: сначала показывается верх, затем следующие секции.

Паузы одинаковые на всех экранах: 2 секунды в конце каждого экрана и 0.8 секунды
между секциями внутри экрана. Иначе один экран «мелькает» на фоне другого (экран
с одной секцией занимал бы меньше времени, чем тот же экран с четырьмя).

## Темы

Роль играется дважды — с тёмной и со светлой темой; каждый ролик остаётся в своей
теме (переключение темы в кадр не попадает). В README тёмный ролик встроен как
`<video src="…">`, а светлый — под `<details>`: GitHub рендерит только `<video src>`
(дочерние `<source>` с `media` он вырезает), поэтому подстановка по теме системы,
как у `<picture>`-схем, для видео недоступна.

## Начальное состояние

- Открыт стартовый экран (`/`) в тёмной или светлой теме — смотря какая тема
  записывается; тема берётся из `localStorage` и применяется до первой отрисовки.
- Курсор стоит слева от формы и до первого действия не двигается.
- История расследований уже наполнена разными запросами (см. ниже).

## Последовательность (что делает сценарий)

1. Набрать запрос об инциденте и отправить расследование.
2. Показать начало обработки (панель «Выполняется»); дальше пауза в ролик не
   попадает (склейка).
3. Показать результат сверху вниз: сводку, симптомы, действия, доказательства,
   ход расследования.
4. Раскрыть черновик issue в блоке «Требуется подтверждение» и подтвердить запись.
5. «История» — сверху вниз, с разными запросами.
6. «Источники» — сверху вниз, до карточек источников.
7. «Диагностика» — сверху вниз, включая блок «Отчёт».
8. «Настройки» — пройти сверху вниз по секциям: модель (01), GitHub (02),
   источники (03), хранилище (04) и строка с кнопкой внизу.
9. Нажать на логотип, вернуться на главный экран — на этом запись останавливается.

Паузы между секциями и в конце экранов одинаковые — см. «Прокрутка».

## История расследований

Экран «История» должен показывать разные запросы, а не один и тот же. История
наполняется настоящими расследованиями через тот же API, что и интерфейс (ничего
в базу напрямую не пишется):

```bash
uv run python -m tools.record_demo --seed
```

Список прошлых расследований задаётся в `HISTORY_SEED` в `tools/record_demo.py`;
там же можно поменять их формулировки. Запуск из самого ролика повторяет один и
тот же запрос, поэтому перед каждой записью его собственный прошлый запуск
удаляется — иначе в истории появился бы дубль, а разнообразие запросов сохраняется.

## Полный порядок обновления ролика

Стенд — локальный `compose` с build-оверлеем; адрес http://localhost:8000/.

```bash
# 0. Один раз: поставить браузер Playwright (нужен также ffmpeg).
uv run playwright install chromium

# 1. Убедиться, что приложение отвечает и отдаёт актуальный интерфейс.
curl -fsS http://localhost:8000/health && curl -fsS http://localhost:8000/ >/dev/null

# 2. Если история пустая или нужны другие запросы — наполнить её.
#    Если история уже такая, какая нужна, этот шаг пропускается.
uv run python -m tools.record_demo --seed

# 3. Записать тёмную тему.
uv run python -m tools.record_demo --theme dark

# 4. Удалить запуск тёмной записи (он повторяет тот же запрос) и перезапустить
#    сервис, чтобы подтверждение записи в светлом ролике прошло без конфликта
#    по дубликату issue.
docker compose -f compose.yaml -f compose.build.yaml exec -T app \
  python -c "import sqlite3,os;c=sqlite3.connect(os.environ['SQLITE_PATH']);c.execute('PRAGMA foreign_keys=ON');c.execute('DELETE FROM agent_runs WHERE id=(SELECT id FROM agent_runs ORDER BY created_at DESC LIMIT 1)');c.commit()"
docker compose -f compose.yaml -f compose.build.yaml restart app

# 5. Записать светлую тему.
uv run python -m tools.record_demo --theme light
```

Проверить длительность и кодек обоих файлов:

```bash
for t in dark light; do
  ffprobe -v error -show_entries format=duration:stream=codec_name,pix_fmt \
    docs/assets/demo-$t.mp4 | grep -E 'codec_name|pix_fmt|duration'
done
```

Если сценарий упал на середине (например, элемент не успел появиться), запуск
повторяют после шагов 4–5 — настройки при этом сохраняются.

## Проверка результата

- Первый кадр тёмный/светлый по теме, курсор виден.
- Между началом обработки и результатом нет дёргающейся полосы — это склейка.
- История показывает разные запросы.
- Все экраны проходятся сверху вниз, прокрутка плавная и медленная; у низа окно
  останавливается, а не дёргается.
- На каждом экране одинаковая пауза (~2 секунды в конце, ~0.8 секунды между
  секциями).
- Последний кадр — главный экран, куда привёл логотип, и курсор на нём виден.
- Ролик не длиннее 40 секунд, H.264, `yuv420p`, `+faststart`.
