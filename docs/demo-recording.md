# Запись демо-ролика

Единственный ролик интерфейса (`docs/assets/demo.mp4`) записывается скриптом
`tools/record_demo.py`: он проходит сценарий целиком в браузере по настоящим
событиям мыши и клавиатуры и перекодирует результат в mp4. Ничего поверх
готового видео не монтируется, результаты не подставляются — в кадр попадает
то, что интерфейс действительно показал в ответ на действие.

## Требования к кадру

- Первый кадр — рабочее состояние интерфейса целиком, вместе с курсором. Начало
  записи (страница до применения темы и до первого движения мыши) отбрасывается.
- Ролик открывается знакомством с темами: тёмная держится 1 секунду, затем
  настоящим нажатием на значок светлой темы включается светлая ещё на 1 секунду, а
  затем — системная. Дальше идёт основной сценарий в системной теме.
- Только реальные состояния и события. Не дорисовывать подсветку, окна и
  результаты; текст не вставляется мгновенно, а набирается.
- Курсор виден весь ролик. Запись идёт из браузера, поэтому указатель рисуется
  слоем внутри страницы, но ездит строго по настоящим событиям `mousemove` —
  тем же, что вызывают наведение и клик. Формы указателя — покадровые вырезки с
  записи экрана macOS, они лежат в `docs/assets/cursor-shapes` и в репозиторий не
  попадают (исключены через `.git/info/exclude`).
- Кадр 1280x800 без масштабирования; тема применяется до первой отрисовки,
  поэтому белого кадра в начале нет.
- Итог: не более 40 секунд, H.264, `yuv420p`, `+faststart`.

## Удержание ролика в 40 секунд

Ролик держится у отметки 40 секунд. Прокрутки — единственное движение, которым
можно менять его длительность, не замедляя паузы: если ролик выходит длиннее,
все прокрутки ускоряются **одинаковым** множителем ровно настолько, чтобы итог
стал 40 секунд, а если короче — наоборот, замедляются (движение идёт плавнее).
Паузы и остальное движение всегда остаются в настоящем темпе. Множитель
выводится из длительности отрезков и суммарного времени прокруток, поэтому
результат детерминирован. Замедление ограничено снизу (не более чем вдвое): если
ролик короче цели сильнее этого предела, прокрутки дальше не растягиваются.

Множитель применяется нарезкой записи по отметкам сценария — отрезки прокрутки
кодируются быстрее или медленнее, паузы идут как есть, — а не повторной записью:
кадры остаются настоящими, меняется только их темп.

## Длительная обработка

Расследование против локальной Ollama занимает минуты. Полностью оно не
показывается: в кадр попадают начало (панель «Выполняется») и результат, а пауза
между ними вырезается склейкой по отметкам времени сценария. Ничего не ускоряется
и не замедляется — между началом и концом просто нет кадров, поэтому полоса не
дёргается. Это не монтаж поверх реальности: оба оставшихся отрезка идут в
настоящем темпе.

## Прокрутка

Прокрутка ведётся колесом мелкими равномерными шагами (~650 px/с) — крупные шаги
читаются как рывки. Дистанция считается один раз и ограничивается фактическим
максимумом прокрутки, а после каждого прохода позиция перечитывается: плавная
прокрутка догоняет событие колеса не мгновенно, и без повторного измерения
дистанция выходит заниженной. У низа страницы смещение равно нулю, поэтому колесо
больше не крутится — окно останавливается, а не дёргается. Экраны проходятся
сверху вниз: сначала показывается верх, затем следующие секции.

Паузы одинаковые на всех экранах: 2 секунды в конце каждого экрана и 0.8 секунды
между секциями внутри экрана. Иначе один экран «мелькает» на фоне другого (экран
с одной секцией занимал бы меньше времени, чем тот же экран с четырьмя).

## Темы

У интерфейса три режима темы — тёмная, светлая и системная; в шапке они показаны
тремя значками рядом, и нажатие на значок включает соответствующий режим. Ролик
играется один раз и начинается со знакомства с темами: тёмная держится 1 секунду,
затем настоящим нажатием включается светлая ещё на 1 секунду, а затем — системная;
дальше идёт основной сценарий в системной теме. Системная на стенде разрешается в тёмную (браузер
эмулирует тёмную настройку ОС), поэтому после светлой переход заметен, а сценарий
идёт в привычном тёмном виде. Тему переключает тот же обработчик, что и у
пользователя: кадр не подставляется, состояние настоящие.

## Начальное состояние

- Открыт стартовый экран (`/`) в тёмном режиме темы — он берётся из `localStorage`
  и применяется до первой отрисовки.
- Курсор стоит слева от формы и до первого действия не двигается.
- История расследований уже наполнена разными запросами (см. ниже).

## Последовательность (что делает сценарий)

0. Вступление: тёмная тема 1 секунда, переключение на светлую на 1 секунду,
   затем переход на системную.
1. Набрать запрос об инциденте и отправить расследование.
2. Показать начало обработки (панель «Выполняется»); дальше пауза в ролик не
   попадает (склейка).
3. Показать результат сверху вниз: сводку, симптомы, действия, доказательства,
   ход расследования.
4. Раскрыть черновик issue в блоке «Требуется подтверждение» и подтвердить запись.
5. «История» — сверху вниз, с разными запросами.
6. «Диагностика» — сверху вниз, включая блок «Отчёт».
7. «Настройки» — пройти сверху вниз по секциям: модель (01), GitHub (02),
   источники (03), хранилище (04) и строка с кнопкой внизу.
8. Нажать на логотип, вернуться на главный экран — на этом запись останавливается.

Паузы между секциями и в конце экранов одинаковые — см. «Прокрутка».

## История расследований

Экран «История» должен показывать разные запросы, а не один и тот же. История
наполняется настоящими расследованиями через тот же API, что и интерфейс (ничего
в базу напрямую не пишется):

```bash
uv run python -m tools.record_demo --seed
```

Список прошлых расследований задаётся в `HISTORY_SEED` в `tools/record_demo.py`;
там же можно поменять их формулировки. Запуск из самого ролика повторяет один и
тот же запрос, поэтому перед каждой записью его собственный прошлый запуск
удаляется — иначе в истории появился бы дубль, а разнообразие запросов сохраняется.

## Полный порядок обновления ролика

Стенд — локальный `compose` с build-оверлеем; адрес http://localhost:8000/.

```bash
# 0. Один раз: поставить браузер Playwright (нужен также ffmpeg).
uv run playwright install chromium

# 1. Если менялся интерфейс (шаблоны, стили, скрипты) — пересобрать и пересоздать
#    сервис. Статика вшита в образ, поэтому одного перезапуска контейнера мало:
#    стенд продолжит отдавать прежний интерфейс. Правки только в
#    tools/record_demo.py или в docs пересборки не требуют.
docker compose -f compose.yaml -f compose.build.yaml build app
docker compose -f compose.yaml -f compose.build.yaml up -d app

# 2. Убедиться, что приложение отвечает и отдаёт актуальный интерфейс.
curl -fsS http://localhost:8000/health && curl -fsS http://localhost:8000/ >/dev/null

# 3. Если история пустая или нужны другие запросы — наполнить её.
#    Если история уже такая, какая нужна, этот шаг пропускается.
uv run python -m tools.record_demo --seed

# 4. Удалить прошлый запуск ролика (он повторяет тот же запрос) и перезапустить
#    сервис, чтобы подтверждение записи прошло без конфликта по дубликату issue.
docker compose -f compose.yaml -f compose.build.yaml exec -T app \
  python -c "import sqlite3,os;c=sqlite3.connect(os.environ['SQLITE_PATH']);c.execute('PRAGMA foreign_keys=ON');c.execute('DELETE FROM agent_runs WHERE id=(SELECT id FROM agent_runs ORDER BY created_at DESC LIMIT 1)');c.commit()"
docker compose -f compose.yaml -f compose.build.yaml restart app

# 5. Записать ролик: он начинается со знакомства с темами и укладывается в 40 секунд.
uv run python -m tools.record_demo

# 6. Обновить ссылку на ролик в README. Файл в README — это asset
#    user-attachments, а не файл репозитория: относительный путь GitHub плеером не
#    покажет. Скрипт грузит новый ролик в отдельном Chrome (на копии профиля,
#    копию и Chrome убирает за собой) и печатает готовый URL для блока **demo**.
#    Навык — ~/.ai/skills/github-non-inlineable-assets/SKILL.md.
python3 ~/.ai/skills/github-non-inlineable-assets/examples/upload_attachment.py \
  --file docs/assets/demo.mp4 \
  --form https://github.com/SlavaKlkv/ai_operations_agent/issues/new
```

Проверить длительность и кодек:

```bash
ffprobe -v error -show_entries format=duration:stream=codec_name,pix_fmt \
  docs/assets/demo.mp4 | grep -E 'codec_name|pix_fmt|duration'
```

Если сценарий упал на середине (например, элемент не успел появиться), запуск
повторяют, повторив шаг 4.

## Проверка результата

- В начале: тёмная тема, через 1 секунду светлая, ещё через 1 секунду системная
  (на стенде — тёмная); дальше весь сценарий в системной теме.
- Между началом обработки и результатом нет дёргающейся полосы — это склейка.
- Прокрутки идут с одинаковой скоростью; если применялся множитель (ускорение
  или замедление), паузы всё равно в настоящем темпе.
- История показывает разные запросы.
- Все экраны проходятся сверху вниз; у низа окно останавливается, а не дёргается.
- На каждом экране одинаковая пауза (~2 секунды в конце, ~0.8 секунды между
  секциями).
- Последний кадр — главный экран, куда привёл логотип, и курсор на нём виден.
- Ролик держится у 40 секунд (не длиннее), H.264, `yuv420p`, `+faststart`.
- Ссылка в README (`**demo**`) заменена на URL, напечатанный шагом 6: ролик в
  README — это asset user-attachments, и без замены там останется прежнее видео.
